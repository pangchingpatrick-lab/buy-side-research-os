# Validated Patterns

This file stores report-writing patterns that have worked well after evaluation.

Do not add raw data here. Add only reusable reasoning patterns, evidence patterns, and report patterns.

## Current Baseline Patterns

### 1. Thinking-Led Reports Beat Framework-Led Reports

Good reports start from a selected thinking path, then use industry frameworks as checklists.

Pattern:

```text
signal cluster
-> causal mechanism
-> value-chain map
-> company exposure
-> financial transmission
-> market expectation gap
-> catalyst / invalidation
-> PM action
```

### 2. Strong AI Infrastructure Reports Need Scarce-Layer Mapping

For AI, semiconductor, datacenter, HBM, CPO, cooling, and power themes, the strongest reports identify the constrained layer before naming companies.

Strong evidence stack:

```text
demand shock
+ capacity / technical / supply constraint
+ customer or capex confirmation
+ company exposure
+ financial line-item bridge
+ market expectation gap
```

### 3. PM-Ready Reports Need Price-In Analysis

A report is incomplete if it states the thesis but does not ask whether the stock or sector already reflects the thesis.

Required bridge:

```text
what market believes
-> what evidence suggests
-> where market may be wrong
-> what catalyst changes the market view
```

## Candidate Patterns To Validate

- Source-weighted evidence chains improve report quality when X signals are treated as leads rather than proof.
- Market reaction data should be paired with earnings and guidance events before making price-in claims.
- Single-name reports need Skill 003 primary more often than broad theme reports.
