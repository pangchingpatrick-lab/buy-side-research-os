# Research Packets

`packets/` stores `research_packet.md` files.

Loop position:

`Data Sources -> Research Packet -> Framework Router -> Industry Framework Repository -> Insight Report -> Validation Questions -> Back to Data Sources`

## Purpose

A research packet is the bridge between classified data and industry-specific buy-side analysis. It should organize the source material clearly enough that `frameworks/framework_router.md` can select the right industry frameworks instead of re-summarizing raw posts.

Use one file per topic:

`packets/[topic]_research_packet.md`

## What A Packet Includes

- research question
- source router
- early signals
- verified evidence
- relevant companies
- source credibility
- data gaps
- contradictions
- current packet status

## What A Packet Is Not

- It is not a final report.
- It is not an investment conclusion.
- It is not a place to invent missing data.
- It is not a research object model.
- It is not a framework selection. Framework selection happens in `frameworks/framework_router.md`.

## Packet Standard

Every packet should make it easy to answer:

- What is the signal?
- Where did it come from?
- Why is the source credible or not credible?
- What has been verified?
- What remains `待验证` or `待补充`?
- Which companies, products, technologies, or value-chain roles are connected?
- Which information types should the framework router consider?
